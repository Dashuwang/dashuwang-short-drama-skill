# 执行规则

1. 按开工路由、小说转脚本、脚本转符、脚本与符转视频的顺序执行；不得从长篇原文直接生成最终视频。
2. 先用少量集数校准改编密度和一组真实回片，再扩批；不得先批量生成再发现全局方向错误。
3. 只制作维持辨识度、连续性或反复使用所必需的符；一次性背景元素直接描述。次要角色默认衣装不自动拆成服装符。
4. 重要符使用唯一 ID，批准后不得覆盖；长期换装、年龄阶段、持续伤势等建立新版本或状态资产。
5. 源脚本、源提示词与模型执行载荷分别保存。模型适配不得改写故事事实、人物身份、对白或资产版本。
6. 执行前核对真实文件、引用顺序、参考数、字符数、时长、画幅、分辨率、编码、声音策略和模型实时能力。
7. 真实提交前持久保存批次 ID、组 ID、提示词摘要、资产清单和 `requesting` 状态；提交一次。响应未知只查询，不重提。
8. 闲时路线必须现场确认闲时开启、精确 0 积分、剩余额度和参数一致；收费、未知或额度耗尽即停，不切换积分或其他付费模式。
9. 任务状态至少区分：`draft`、`preflight_passed`、`requesting`、`submitted`、`generating`、`downloaded`、`tech_passed`、`content_passed`、`cut_passed`、`delivered`、`uncertain`、`failed`。
10. 失败原因至少区分：平台拒绝、依赖资产阻塞、文字拒绝、通用生成失败、额度/并发阻塞、本地写入失败和未知提交。不得把主动跳过算作平台拒绝。
11. 只下载真实原任务的无水印结果；先临时落盘、解码与摘要核验，再原子替换正式文件。半文件不得进入剪辑。
12. “文件齐全”不等于“内容通过”；技术、人物/服装/场景、对白/口型/声线、镜头节奏和分集接缝分别验收。
13. 出现问题时先判断属于脚本、资产、视频提示词、模型执行还是剪辑，不新增系统层掩盖根因。
14. 单部剧的数据只能进入测试项目，不能写入通用 Skill。
