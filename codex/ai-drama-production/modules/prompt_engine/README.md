# Prompt Engine 模块

只从已批准的结构化 Shot、已确认资产和项目配置生成视频提示词。提示词属于表达层，不得反向修改故事事实、人物身份、资产版本、对白或镜头目标；不得从小说原文直接生成最终视频提示词。

## 输入门槛

生成前必须确认：

- Shot 已批准，且包含镜头编号、时长、剧情与情绪目标、动作、表演、对白及连续性。
- 人物、精确状态、场景时间与状态、道具和本镜所需技能符均已登记并确认版本。
- 每位出镜角色有本组所需、已穿好合适衣装的已确认人设／换装／状态图；只交提示词时可标待装载，但不得声称已经可提交。视频前缺图或错装先补资产，不能用文字临时换衣。
- 项目全局风格与本镜覆盖项明确。

任一必需项缺失时，返回缺失项并停止生成最终提示词；容量、对白或连续性问题退回 `shot_design`。

## 各模式共同遵守：声画同出

每组把「对白、心声、剧情画外声及环境/动作声由同一次视频生成随画面输出，保留可听的随片原音，不单独配音或后贴」写进本组提示词，无台词也给场景底声或动作声。A 版放在 `【提示词】` 的对白与声音段，不增加第五区。心声和剧情画外声是同一视频任务内部的声源标记，画内听者不对口型；声线符、声音气质和音区示意都不是要另做的配音轨。修改或适配提示词不得移除该约束。

## Self V0.2 执行顺序

1. 核对 Shot、精确状态名、场景时间与状态、道具、对白、连续性和实际可用资产。
2. 建立团队参考框装载清单，只列本镜实际需要的资产；逐人核对适用衣装图、版本、文件和顺序。
3. 继承项目全局设定，只追加本场或本镜特殊要求。
4. 生成固定四区 `【镜头编号】`、`【资产】`、`【全局设定】`、`【提示词】`。
5. `【提示词】`第一开头写“承接上一镜头”并自然语言复述人物及精确状态、场景时间与状态；中段引导演员动作、眼神、停顿、表演和镜头调度，同时保留合理发挥空间；结尾写“本镜头最终目标”。
6. 对白逐字保留；不得退化为 B 版，不得用秒级时间线、焦段参数、机位坐标或逐帧动作越界为 TD。
7. 写入 `engine_version=self_prompt_engine_V0.2`、`mode=self` 和输入版本，不覆盖历史记录。

自然语言调用资产，不使用 `@图片` 语法。`【资产】`供团队装载参考，正文仍复述人物、精确状态与场景；服装款式、颜色、面料、纹样、鞋履和配饰设计不再复述，也不能移入全局区或平台派生提示词。叙事必要的衣物交互动作可写，但不得借机重新设计衣装。

`self_prompt_v0.1/` 原样保留供历史项目回溯，新输出默认 V0.2；不覆盖旧稿或自动重做已确认资产。

原纯接口版本保存在 `history/v0.1/`，用于追溯，不参与当前路由。

## 与模型适配器的边界

四区结果是可审阅的源提示词，不等于任何平台的最终提交载荷。选择平台后，由 `modules/model_adapter/` 建立派生执行提示词、有序参考图、参数和任务记录；适配器可以按平台能力加入时间段和技术限制，但不得覆盖四区源提示词、改写对白、改变资产版本或悄悄删减拍点。Vidu 闲时路线读取 `modules/model_adapter/vidu_nopeak_v0.1.md`。
