# 核心范围与验收 V0.3

## 三项核心能力

| 阶段 | 当前状态 | 最小合格输出 |
|---|---|---|
| 小说改编成脚本 | testing | 分集短剧脚本，包含场次、动作、原样对白、冲突、节奏与钩子 |
| 脚本生成符提示词 | rune format frozen / selection testing | 必要符清单及可直接复制的完整制符提示词 |
| 脚本与符生成视频 | testing | 每个生成片段的符清单、视频提示词和模型必要参数 |

版本、资产表和质量检查只保障以上三项，不作为第四个核心阶段。

## 精简验收

使用不同题材样本各验证一次，全部满足才冻结 V0.3：

1. **脚本**：改编不机械切原文；单集有推进和钩子；对白、动作关系正确。
2. **符**：核心资产不漏；一次性背景不滥制符；提示词遵循冻结模板并可直接复制。
3. **视频提示词**：正确使用已确认符；15 秒内有足够剧情内容；动作、台词、表演和镜头调度可执行。
4. **结果**：生成失败能明确归到脚本、符、提示词或模型之一，不增加新系统层掩盖问题。

## 禁止扩张

- 不为可能用不到的未来功能提前创建模块、Schema 或复杂路由。
- 不建立通用评分系统、复杂资产依赖图或大而全数据库。
- 新功能只有在真实测试暴露明确缺口时才加入，并优先写进现有三个阶段。
