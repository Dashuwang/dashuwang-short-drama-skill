# 大叔汪 AI 短剧生产系统

只维护三个核心阶段：**小说改编成脚本、脚本生成符资产、脚本与符生成视频**。执行、台账、质检和剪辑只作为这三个阶段的轻量保障，不扩张成平行系统。

## 快捷启动语

把原小说的**文件路径、所在文件夹路径，或当前项目里的文件名**和「**大叔汪开始做新剧**」发在同一条消息里，不用另传一遍文件或补写技能名。也可以只发启动语，再补原著。

先按[开工卡的原著定位规则](references/project-intake-and-routing-v0.5.md#原著定位)查找原著。唯一可读时直接读原著并开始理解，缺失的开工项用点选卡确认；信息齐全即可进入试写，不再另问一次是否开工。仍保留剧本、资产和首条提示词的确认点；启动语不自动授权远程生成、积分消费或覆盖已有项目。

## 工作状态文案

执行需要等待或多步处理的工作时，读取 `references/work-status-copy-v0.1.md`，使用“大叔汪干活碎碎念”作为简短状态更新。文案只表达可核实的当前阶段，不展示隐藏思考过程；每个有效阶段最多一条，不刷屏、不虚报完成，不得用玩笑代替费用、权限、失败或用户选择提示。结构化文案池见 `config/work_status_copy_v0.1.json`。

## 开工路由

新项目使用[新剧开工卡](assets/project-intake.html)：标准项只点选，只有一个「特别要求」自由输入框；已明确的值直接继承。宿主不能提供符合要求的原生卡片时，交付本地 HTML 供浏览器点选并复制／导出回传，不发逐题文字问卷。

1. 原著文件、制作范围与版权/授权边界。
2. 改编策略：原著完整保留、适度压缩、自由改编或原创。
3. 画风：真人写实、轻写实 3D、国漫、二维动漫或其他明确风格。
4. 题材与受众：题材 + 男频 / 女频 / 通用。
5. 成片画幅：横版 16:9 或竖版 9:16。
6. 单集时长、预计集数或总时长预算。
7. 制作路线：
   - `vidu_nopeak`：Vidu Q4 闲时创作，必须实时确认闲时资格和 0 积分；
   - `seedance`：再选择即梦、Higgsfield 或用户指定平台；
   - `prompt_only`：只交付剧本、资产提示词和视频提示词，不远程生成。

可选再确认协作节奏：快速、稳妥或逐步。默认“稳妥”，在试写剧本、关键资产、首条视频提示词三个位置停下。

详细交互、默认值与路由条件见 `references/project-intake-and-routing-v0.5.md`。

## 开始前

1. 读取 `PROJECT_KNOWLEDGE_BASE.md`、`core/workflow.md` 和当前项目的 `CURRENT.json` 或等价当前入口；没有当前入口时创建最小入口。
2. 只读取当前阶段需要的模块，不预加载无关资料。
3. 涉及制符时，先读 `modules/rune_generation/README.md` 与 `asset_prompt_format_v0.5.md`；不得沿用旧人设或纯衣物模板覆盖新版。技能符仍读独立模板。
4. 涉及视频提示词时，读取 `modules/shot_design/`、所选 `modules/prompt_engine/` 与目标 `modules/model_adapter/`。
5. 涉及真实生成时，先读取目标工具当前能力与额度；历史参数只作案例，不能代替实时能力探测。

## 三个核心阶段

### 1. 小说改编成脚本

调用 `modules/adaptation/`。先冻结范围、改编自由度、揭示顺序、对白政策和时长预算；再用少量集数试写，用户确认密度后才扩批。

按 `modules/adaptation/screenplay_format_v0.5.md` 交付正式稿：先写适用于全剧的制作总则，再写本集独有信息、逐组正文、声音负载和资产预登记。短剧按有效剧情拍点分配时长；12—16 秒生成组通常包含 3—5 个因果连续微拍点，不能用慢动作、凝视和空镜填满容器。

### 2. 脚本生成符资产提示词

从已确认脚本中识别必须稳定复现的人物、必要换装、场景、道具、生物、界面、角色状态与技能方法。先复用已有符，只为必要对象创建或升版。

所有入选资产必须使用完整独立模板，不因“次要”而用“同上”或缩写。次要角色的一套默认衣装通常保留在人设符内；只有主要人物的长期换装、标志性衣装或连续性高风险衣装才单独制作服装符。状态变体必须由已确认人物图派生，不得纯文字另造一张脸。

生成成功、视觉通过和用户锁定必须分别记录；只有关键资产锁定后才能批量进入视频阶段。

### 3. 脚本与符生成视频

调用 `modules/shot_design/` 把脚本整理成 12—16 秒生成组，再调用 `modules/prompt_engine/` 生成可追溯的源提示词。每组保留 3—5 个微拍点，单个可见分镜通常不少于 1.2 秒且不超过 5 秒；对白必须绑定动作节点。

目标模型适配只生成派生执行载荷，不覆盖源提示词。执行前必须核对资产装载顺序、真实文件、模型上限、时长、画幅、编码、声音策略和费用/闲时状态。首组真实回片通过后才扩批。

选择 Vidu 闲时创作时读取 `modules/model_adapter/vidu_nopeak_v0.1.md`。优先使用当前可用的 FRAME 直接 `nopeak` 路线；只有直接路线不可用且用户选择旧网页路线时才使用网页闲时队列。收费、额度未知或参数不一致立即停止，绝不静默切换积分、`normal` 或 `claw_pass`。

## 固定验收门

1. **开工卡通过**：范围、改编策略、画风、受众、画幅、时长和工具路线明确。
2. **试写通过**：样例集的事件密度、对白政策、集尾钩子和总时长预测通过。
3. **关键资产通过**：身份、服装、场景结构与状态版本锁定。
4. **首组回片通过**：技术规格、人物/服装/场景一致性、对白、口型、声音和镜头密度通过。
5. **分集交付通过**：素材齐全、技术核验、内容核验、初剪/精剪阶段和文件摘要分别可查。

## 不可偏离的规则

- 符就是资产，包含资产符和技能符；不是所有流程都要变成符。
- 制符提示词保持冻结的 `【】` 分区和横向信息资产板格式，不退化为关键词堆砌、单张立绘或普通概念图。
- 对白默认逐字保留；需要改稿必须记录授权、原稿、修改差异和新版本。边做边说的台词必须绑定动作节点。
- 生成组是模型容器，不是传统单镜；不得把 3—5 秒内容拉满 15 秒，也不得把一集拆得过碎。
- 资产栏与真实上传清单必须一致，顺序必须一致；未上传的资产不能在执行记录中写成已装载。
- 任务提交前持久化唯一身份；响应不明记 `uncertain`，只查询原任务，禁止盲目重提。
- “生成成功、已下载、技术通过、内容通过、初剪完成、精剪完成、已发布”是不同状态，不能用一个 success 混算。
- 单部剧只作为测试样本；角色、场景和剧情不得写进通用规则。案例进入 Skill 时必须去项目化。
