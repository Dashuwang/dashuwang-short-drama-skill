# 精简完整制作流程 V0.4

这是一条生产线，不是新增模块。步骤分别落在三个核心阶段中。

| 步骤 | 做什么 | 必需产物 | 通过标准 |
|---|---|---|---|
| 0 开工路由 | 回答七项开工卡，选择平台 | 项目配置、当前入口 | 范围、策略、画风、受众、画幅、时长、平台无歧义 |
| 1 原著理解 | 建章节/事件/人物关系和不可改事实 | 故事理解、事实表、范围表 | 未把未读内容写成已确认；后续接续位置清楚 |
| 2 试写改编 | 先写少量集，校准密度 | 试写剧本、时长预测 | 开头有钩子；每3—5秒有拍点；对白政策正确；集尾有新问题 |
| 3 批量剧本 | 按批准样例扩展 | 分集剧本、场次、资产候选 | 因果连续；没有机械切原文；范围和总预算可追踪 |
| 4 资产盘点 | 复用、创建、升版或内联描述 | 必要资产表 | 核心不漏；默认衣不滥拆；一次性背景不滥做符 |
| 5 资产制作 | 生成完整资产板并锁定 | 提示词、成图、版本与审核 | 文件、身份、画风、文字/结构、用户确认分别通过 |
| 6 生成组设计 | 剧本拆成模型容器 | 12—16秒生成组表 | 3—5微拍点；单镜通常1.2—5秒；动作对白锚点正确 |
| 7 提示词与适配 | 先源提示词，再平台载荷 | 源提示词、挂图顺序、参数计划 | 台词不乱；资产与真实上传一致；模型限制预检通过 |
| 8 首组回片 | 只生成一组或一集样片 | 真实任务、无水印文件、首组报告 | 技术、人物、服装、场景、声音、台词和节奏都通过 |
| 9 批量执行 | 按额度与并发分批提交、回收 | 任务台账、下载文件、异常表 | 无重复提交；未知状态冻结；缺口与失败原因可查 |
| 10 分集整理 | 按剧情切点剪成单集 | 初剪、拼接顺序、核验文件 | 台词句尾完整；最长单镜受控；接缝与总时长通过 |
| 11 交付 | 分级报告与归档 | 素材/初剪/精剪/发布包 | 只报告实际达到的等级，当前版本入口指向有效文件 |

## 三次小批量原则

1. **剧本先试写**：一至数集，防止全量改编方向错误。
2. **资产先做关键项**：主角、核心场景和关键道具，防止全量画风或模板错误。
3. **视频先做首组/首集**：回读实际模型、时长、编码、参考数、声音和质量，再扩批。

## 最小项目入口

项目应保留一个 `CURRENT.json` 或人类可读等价文件，只指向当前有效版本：

```json
{
  "project_version": "",
  "script": "",
  "asset_registry": "",
  "prompt_index": "",
  "task_ledger": "",
  "cuts": "",
  "delivery_level": "script|assets|materials|rough_cut|fine_cut|published"
}
```

旧稿保留为历史，不批量破坏旧路径，也不能继续作为默认入口。

## 用户可见确认点

- 开工卡；
- 试写剧本；
- 关键资产；
- 首条视频提示词与首组回片；
- 最终交付等级。

快速模式可以减少中间打扰，但不允许跳过内部预检、资产验证、真实 0 积分确认和首组回片验证。
