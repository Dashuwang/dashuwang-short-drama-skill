# 项目开工点选与路由 V0.5

## 原著定位

沿用 [V0.4 原著定位规则](project-intake-and-routing-v0.4.md#快捷启动与原著定位)，不沿用其中的文字问卷。用户在聊天里贴原著位置／附件和「大叔汪开始做新剧」。唯一原著可读时先读取；多个候选时在开工卡加单选，不逐个问。无法定位时直接说明并请附文件或贴路径，此为提供素材，不是另加作答框。

## 交互规则

用能真正点击的表单，不把 Markdown 列表、假的按钮或逐题输入框当作点选。已知项目参数直接继承，只填缺项。普通字段全部单选；整张卡只允许一个自由文本字段 `special_requirements`（「特别要求」）。指定章节、自定义画风与时长、其他平台等全部走这个字段，不出现独立的 Other / 补充框。

- 有支持整张卡、且能禁用各题自由输入的宿主表单时可原生展示；工具若每题自带自由输入且不能禁用，不使用该工具来冒充本卡。
- 通用实现：[新剧开工卡](../assets/project-intake.html)。将本地 HTML 链接交给用户在浏览器打开；单选后可「复制开工卡」一次贴回，或上传导出的 JSON。它不自动把结果交回对话，也不远程执行。浏览器限制复制时自动提供下载。没有表单表面时仍提供此文件，不降级成文字问卷。
- 可用 URL fragment `#prefill=<URL 编码的 JSON>&candidates=<URL 编码的 JSON>` 带入已确认选项和原著候选。`prefill` 为表单字段名到已知选项值；`candidates` 为 `[{"id":"source1","label":"候选文件名"}]`，实际路径由当前会话按 ID 解析。只将必要的选项与候选显示名放入链接，不放小说原文、绝对路径或私密信息。不支持 fragment 时交付通用卡，导入以本对话已确认值为准；只有用户明确要求变更才覆盖。

## 点选字段与导入

点选制作范围、授权状态、改编策略、画风、题材、受众、横竖、单集时长、总量和制作路线。只有选 Seedance 才显示平台（即梦、Higgsfield、其他）。协作节奏默认「稳妥」，有特殊偏好写入特别要求。没有默认勾选的选项不得当作已确认；「待确认」「先给建议」只进入规划，不代表可扩批、生成或发片。

开工卡导出 `format: dashuwang_drama_intake_v0.5`、`answers` 和 `special_requirements`。核对项目原著与选项，映射到 `templates/project_intake.template.json`（例如 `source_scope → source.scope`、`rights_boundary → source.rights_boundary`）；`special`、`selected`、平台 `other` 读唯一的特别要求，先解决实际边界，再写已确认配置。把「不要 BGM」等跨集要求放入剧本总则；单集例外写到对应集。禁止把特别要求当作未核实的执行权限。

Vidu 闲时只走直连，不操作网页，提交前同时核对原音输出证据、实时零费和正额度；Seedance 当前按已选平台交提示词及预检；只交提示词不调用生成。开工卡通过不替代试写、关键资产、首组与费用确认。沿用剧本／模型请求／实际回片／成片四层时长记录。
