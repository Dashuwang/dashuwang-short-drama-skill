# 核心工作流

版本：V0.5.1-testing

## Stage 0 开工路由（不是第四个核心阶段）

用开工点选卡冻结原著范围、改编策略、画风、题材与受众、成片画幅、时长预算和制作平台。仅「特别要求」可自由输入。建立 `CURRENT.json` 或等价入口，指向当前剧本、资产、提示词、任务与成片版本。

## Stage 1 小说 → 脚本

先完成故事理解、原著事实表、改编政策和总时长预测，再试写少量集数。样例通过后扩展分集、场次和短剧节奏。输出包含人物、场景、动作、原样对白、内心声归属、冲突、微拍点、每集目标、集尾钩子和新增资产候选。

正式剧本总则写全剧，不写成首集说明；之后是分集头、逐组正式正文和声音负载／资产预登记，详见 `modules/adaptation/screenplay_format_v0.5.md`。

## Stage 2 脚本 → 符提示词 → 符资产

从已确认脚本挑出必须稳定复现的资产和技能方法。默认服装留在人设中，必要换装才独立；状态与年龄变体由锁定人物资产派生。每项入选资产输出完整独立提示词。生成后分别记录文件存在、视觉质检、用户确认与锁定版本。

人物盘点完成后，按[差异规则](../modules/rune_generation/character_differentiation_v0.1.md)先交付一张全剧差异 CSV、完成文字横向对照，再逐人写提示词。续作在旧主表补行；真实成图按近似角度并排复核，不用文字检查冒充视觉通过。

## Stage 3 脚本 + 符 → 视频提示词 → 视频素材

把脚本整理成 12—16 秒高密度生成组，为每组选择已确认资产，生成动作、对白、表演、声音和镜头调度明确的源提示词。目标适配器再建立有序挂图、参数和执行载荷。

真实执行分为：预检、首组验证、批量提交、任务回读、无水印下载、技术验收、内容验收、分集初剪。剪辑与发布可以继续，但不改变三个核心阶段。

## 确认与授权

创作确认点：试写脚本、关键资产、首条视频提示词/回片。真实生成另受费用授权约束：闲时路线也必须证明 0 积分；任何收费生成必须展示实际报价并取得数字上限。

禁止在三个阶段之外新增平行核心流程；版本、台账、审核、下载和剪辑只能作为轻量辅助。
